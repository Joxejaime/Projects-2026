# orders-api

Owner: **team-orders**  |  Tier: **standard**  |  Availability target: **99.9%**

Generated by `platformctl new` from the platform golden path. It ships with a health-checked service,
tests, a hardened container, Kubernetes manifests and a CI pipeline, so the first deploy works the day
the repository is created.

## Develop
```bash
python -m unittest discover -s tests -t .     # run tests
PORT=8080 python -m app.main                 # run locally
docker build -t orders-api:dev . && docker run --rm -p 8080:8080 orders-api:dev
```

## Guardrails
Run the platform checks before opening a pull request (from the platform repository):
```bash
python -m platformctl validate path/to/orders-api
```
They cover: pinned images from approved registries, resource requests/limits, non-root, no privilege
escalation, probes, minimum replicas for the `standard` tier, required ownership labels.

## Operate
- On-call runbook: [`docs/runbook.md`](docs/runbook.md)
- Tier `standard` means 2 replica(s) by default and a PodDisruptionBudget.
  To change tier, edit `service.yaml` and re-run validation; do not hand-tune replica counts below the tier minimum.
